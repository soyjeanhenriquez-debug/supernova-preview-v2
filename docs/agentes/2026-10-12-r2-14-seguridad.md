## Hallazgos por gravedad

### ALTO-1 · ai-chat: reembolso por "respuesta cortada" se fuerza a voluntad
- Archivo: `supabase/functions/ai-chat/index.ts:171` (detecta `finish_reason:"length"`) y `:283` (reembolsa).
- Cómo se explota: el cliente manda su propio `systemPrompt` y mensajes. Pide el entregable y "después rellena hasta 20.000 palabras". La IA llega al tope (8.000 tokens), se devuelve el cobro completo y el texto ya llegó. Hasta 300 al día por persona (≈ US$0,024 c/u → ~US$7/día, más que su PRO al mes en 4 días).
- Arreglo (dueño de ai-chat): tope de 2 reembolsos por corte al día.
```diff
-        generatorId ? () => refundCharge(gate, "respuesta cortada (tope de largo)") : undefined)
+        generatorId ? async () => {
+          // Tope: 2 reembolsos por corte al día (se puede forzar pidiendo texto infinito).
+          const since = new Date(Date.now() - 86_400_000).toISOString();
+          const { count } = await guardClient().from("credit_transactions").select("id", { count: "exact", head: true })
+            .eq("user_id", gate!.userId).eq("action", "refund").gte("created_at", since)
+            .eq("meta->>reason", "respuesta cortada (tope de largo)");
+          if ((count ?? 0) >= 2) return;
+          await refundCharge(gate, "respuesta cortada (tope de largo)");
+        } : undefined)
```
(credit_transactions por usuario y 24 h: consulta chica, no es winning_ads.)

### MEDIO-1 · whop-webhook: activación sin plan legible daba acceso — ARREGLADO (local)
- Antes: `evPlanId` solo leía `plan.id` o `plan_id`. Si Whop manda `plan: "plan_…"` (texto), el id quedaba vacío, se saltaba `SUPERNOVA_PLANS` y una membresía de CUALQUIER producto abría la app.
- Ahora: `planIdOf()` lee objeto, texto, `plan_id` y la membresía; y una activación (active/trialing) de membresía SIN plan no da acceso (las bajas sin plan sí se aplican).

### MEDIO-2 · whop-webhook: créditos por texto que escribe quien compra — ARREGLADO (local)
- Antes: `detectPack` buscaba "boost 500 / power 2000 / nuclear 4500" en `metadata`, `membership` y `name`. Quien comprara un producto gratis de Jean con ese texto en metadata recibía el pack.
- Ahora: primero por id de plan; el respaldo por título solo mira datos del producto/plan (los pone Jean) y nunca si el plan es de suscripción.

### MEDIO-3 · Pack reembolsado se quedaba con sus créditos — ARREGLADO (local + migración)
- Antes: un reembolso/contracargo de pack se ignoraba (`skipped: pack:…`).
- Ahora: `whop-webhook` llama `revoke_pack_credits` (o `revoke_media_pack_credits`): quita lo COMPRADO que aún quede, hasta el tamaño del pack (lo gastado no se cobra; los del mes no se tocan), anota `pack_refund` con cost 0 y anula el cashback pendiente de ese pack. Idempotente por id del reembolso (`whop_refund:<id>` en stripe_events). Necesita la migración; sin ella responde 500 y Whop reintenta (queda `PACK_REEMBOLSO_PENDIENTE` en logs).
- Recordatorio: Whop no envía eventos de reembolso hasta que Jean los active (memoria 29-sep).
